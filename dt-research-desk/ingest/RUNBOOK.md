# Weekly ingestion runbook

Rebuilds the **Dual Trend Desk** dashboard from a market-research analyst's Slack output.
Run automatically by two scheduled tasks against a **shared watermark**, so whichever fires first
processes whatever is new:

| Task | When | Covers |
|---|---|---|
| `dt-friday-brief` | Fri 21:12 local | the Weekly Brief — performance pair, cash level, call outcomes |
| `dt-weekly-ingest` | Mon 21:40 local | the S&P 1500 ranking report and its workbook |

Both run the same incremental sweep; the split exists so the performance series lands the same evening
rather than waiting until Monday. Everything is incremental — a missed run just catches up on the next.

## Layout

```
dt-research-desk/
  index.html                 generated — never edit by hand
  ingest/
    state.json               watermarks + processed-file inventory
    data/*.json              curated records (trades, calls, perf, regime, persistence, copy, meta)
                             — all gitignored: they carry licensed third-party content
    data/rankings.json       generated by parse_xlsx.py
    corpus/pdf/  corpus/xlsx/  downloaded sources
    txt/                     generated by extract_pdf.py
    template/                head.html, body.html, app.js
    build-manifest.json      provenance of the last build (owner, payload hash, counts)
    .pipeline.lock           present only while a build is in flight
    lib/                     extract_pdf.py, parse_xlsx.py, build.py,
                             validate.py, verify_build.py, guard.py,
                             preflight.py, record_publish.py
```

## Sequence

**1. Diff the channels.** Read both since `state.json → channels.*.last_ts`. Channel ids and the
author filter live in `state.json → channels` — this file names no workspace identifiers.
- trade channel — portfolio actions
- publishing channel — research PDFs and ranking workbooks, filtered to the analyst's author id

**2. Append new records to `data/`.** One object per new item; keep the existing schema.
- Portfolio action → `trades.json`
  `{date,ticker,name,action:BUY|ADD|TRIM|SELL,direction,size,asset,sector,theme,rationale,source:"slack",url,conviction}`
  Slack permalink: the workspace archive URL for that channel + `/p` + the ts with the dot removed.
- Research report → `calls.json`
  `{date,subject,category,direction,conviction,thesis,evidence,pdf,url,status}`
- Weekly Brief → also append to `perf.json` `{date,dt,spx,cash}` — the "Through Thursday's close" line
  and the cash level. This is the **only** source for the performance series.
- Notable regime shift → `regime.json` `{date,title,dir:bull|bear|neu,body}`
- Then revisit `persistence.json`: for any prior call on the same subject, set `outcome` to
  Held / Faded / Reversed / Confirmed and update `note`. This table is the point of the exercise —
  it is what makes the dashboard more than an archive.

**3. Download new files.** *Needs a human — see Limits.* Slack desktop → Files tab → search the
filename → click the row → preview modal → Download. Lands in `~/Downloads`. Then:
```
cp ~/Downloads/<file>.pdf   ingest/corpus/pdf/YYYY-MM-DD_ShortName.pdf
cp ~/Downloads/<file>.xlsx  ingest/corpus/xlsx/SP1500_YYYY-MM-DD.xlsx      # or Thematic_
```
Name PDFs by **post date**; name workbooks by the **data date in the filename**.
If a file cannot be fetched, add it to `state.json → pending_download` and carry on.

**4. Rebuild.** Set `DT_OWNER` so the build is attributable.
```bash
cd dt-research-desk
DT_OWNER=dt-friday-brief python3 ingest/lib/parse_xlsx.py \
  && python3 ingest/lib/extract_pdf.py \
  && DT_OWNER=dt-friday-brief python3 ingest/lib/build.py
```
`build.py` takes the pipeline lock, runs `validate.py` and refuses to build if it errors, writes
`index.html` atomically, runs `verify_build.py` on the output, and stamps `build-manifest.json` with
owner, payload hash and counts. A failure at any gate aborts the build rather than publishing damage.

**5. Preflight, then republish.** Never publish blind — more than one session has written here.
```bash
# WebFetch the artifact first; it saves the page to a local file
python3 ingest/lib/preflight.py <the-file-WebFetch-saved>
```
| exit | meaning | do |
|---|---|---|
| 0 | local differs, live is our own last publish | publish, then `python3 ingest/lib/record_publish.py` |
| 3 | live already matches local | **skip** — nothing changed |
| 2 | **conflict** — live is not what we last published | **do not publish.** Someone else did. Read the live version, fold in anything missing, rebuild, retry |

Publish with `url` from `state.json → artifact_url` so the link is kept, then record it.

**6. Update `state.json`**: both `last_ts`, `last_run`, the processed inventories, `pending_download`.

## Gotchas

- **Report date = data date + 3.** A Monday report carries the prior Friday's workbook. Charts key on
  the *data* date. Don't mix them.
- **Universe size is not fixed.** Row counts drift week to week, and one snapshot jumped by ~45 rows.
  Always express breadth as a percentage of that snapshot's row count, never as a raw count.
- **Duplicate filenames.** Some briefs are posted under an identical filename in different weeks.
  Disambiguate by file size or by the date printed on page 1.
- **Header row is row 3** in every workbook sheet.
- **Browser verification silently stops verifying if the working copy moves.** The preview only
  *executes* scripts for files inside the session's project folder; outside it, it renders a static
  snapshot and `javascript_tool` fails with "No site is open in this tab" — a step written as "open it
  and check the console" then passes vacuously. `verify_build.py` covers the same ground without a
  browser (mount points, data round-trip, external hosts, unrendered template literals, theme tokens)
  and runs automatically at the end of every build. Granting directory access does not fix the preview;
  only moving the copy back inside the project folder does.
- **Scheduled-task definitions are global, not per-session.** They live in `~/.claude/scheduled-tasks/`
  and any session can rewrite any task's prompt with no conflict marker and no notice. Two sessions
  repointed these tasks at different trees within an hour of each other. Before editing a task, say so;
  after editing one, check it still targets the tree named in `state.json → pipeline_id`.
- **Slack file search returns tree entries as well as blobs.** Filtering only on the path prefix inflates
  every count. Always add `select(.type=="blob")`.
- **You are not the only writer.** A forked session republished this artifact once while the schedule
  was live. The lock, the preflight check and `build-manifest.json` exist because of that. If preflight
  returns CONFLICT, something else is driving the pipeline — find it before publishing.
- **Never compare perf dates against the latest trade.** A Friday brief lands on days with no portfolio
  action; an earlier version of `validate.py` rejected exactly that and would have blocked a weekly run.
  Future-date checks compare against the clock.
- **Permalinks must come from the post you are citing.** A research call links into `#mo-publishing`
(the publishing channel), a portfolio action into the trade channel. It is easy to reuse an adjacent
  timestamp and produce a link that resolves to the wrong post — this happened to four calls on the first
  build. Before publishing, assert every `calls[].url` contains the publishing channel id and every
  `trades[].url` the trade channel id, both read from `state.json`. If a post has no verified timestamp,
  set `url` to `null` and rely
  on the `pdf` field; a wrong link is worse than no link.
- **Not every report is posted by the analyst.** At least one report was posted by a colleague, so the
  author filter misses it. When a PDF is referenced in a Weekly Brief but absent from the filtered posts,
  search the channel by filename.
- `index.html` is generated. Edit `template/` or `data/`, never the output.

## Limits

The Slack connector reads messages and file *metadata* but cannot download file *bytes*. Retrieval runs
through the Slack desktop app via computer-use, which requires a per-session approval dialog — so
**step 3 cannot run unattended**. An unattended run does steps 1, 2, 4, 5, 6 and leaves the new files in
`pending_download` with exact filenames. The next attended run picks them up.

Consequence: an unattended Monday run refreshes the *message-derived* layers (trades, calls, performance,
timeline) but the ranking charts stay at the last downloaded snapshot until someone approves the fetch.
The run report says which layers moved.
